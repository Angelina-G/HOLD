## 修复：「我的」tab 图标不显示

- 现象：tabBar 第 4 项「我的」无图标。`app.json` 配置本身正确，问题在 PNG 文件内容。
- 前两次生成失败：几何用「大圆弧 + 挖空」思路，超采样距离场算错，
  产出实心色块（bbox 79×56 顶到画布边缘、2319 像素），且形状完全不像人像。
- **正确做法（可复用）**：改用 **无符号距离场（SDF）+ 4× 超采样**。
  - 头部 = 圆环：`abs(hypot(p-c) - r)`
  - 肩部 = 圆弧：`theta = atan2(dx, -dy)`，`|theta| <= thetaMax` 时取 `abs(dist - R)`，
    否则回落到弧两端点的距离（这样圆弧有干净的圆头端点）
  - 描边宽度 5.5px 与现有图标（5~6px）一致：`alpha = clamp(half - d + 0.5, 0, 1)`
  - 几何：`HEAD={x:40.5,y:28,r:10.5}`、`BODY={x:40.5,y:79.5,r:32.5,θmax:60°}`
  - 结果 bbox 63×52，中心 (40, 39.5)，888 像素 —— 与 home(61×56)、history(59×59) 同规格
- 顺带把 `pages/profile` 登录卡片插画从复用 `tab-user-active.png`（81px 放大会糊）
  改为独立生成的 `images/login-avatar.png`（168×168，同款 SDF 几何等比缩放）。
- 图标生成脚本思路记在 `~/.workbuddy/skills/wechat-miniprogram-cloud-user-system` 相关笔记里，
  以后需要新增 tab 图标可直接复用这套 SDF + PNG 手写编码方案。
- 验证：Pillow 交叉校验全部 9 个 RGBA 资源；node 桩环境冒烟跑通 profile 页
  （onLoad / applyAccountState / applyRuntimeState / onUnload）+ tabBar 配置校验 + 45 个样式类覆盖。

### 真正根因（第一轮误判，第二轮才找到）

上面第一轮把原因归到「PNG 图形畸形」是**误判**。修好图形后图标依然不显示，
重新排查才找到真凶：

**`project.private.config.json` 的 `"ignoreDevUnusedFiles": true`**

这是开发者工具「详情 → 本地设置 → 忽略无依赖文件」开关。开启时 DevTools 按
**依赖图缓存**剔除它认为没被引用的文件。新增图片若只被 `app.json` 的 tabBar
引用，依赖图缓存未刷新就会被过滤出编译产物 → **tabBar 文字照常显示、图标区空白**。

判定依据（这套排除法很管用）：
1. `app.json` tabBar 配置逐项校验通过（pagePath 已注册、iconPath 文件存在）；
2. 生成的 PNG 与能正常显示的图标**逐字节同构**（同为 8bit RGBA、非隔行、
   IHDR/IDAT/IEND、CRC 全 OK），Pillow 也能正常解码 → 排除编码问题；
3. 全项目搜索 `setTabBarItem` / `custom-tab-bar` / `"custom":` 均无命中 → 排除运行时覆盖；
4. `packOptions.ignore` 只忽略两个无关文件夹 → 排除打包过滤；
5. **决定性证据**：三个内容完全不同、像素数分别 1344 / 2319 / 888 的图片
   全都显示不出来 → 内容不是原因，是文件根本没进编译产物。

修复：`project.private.config.json` 改 `"ignoreDevUnusedFiles": false`，
再「清缓存 → 重新编译」。真机预览对应的是 `ignoreUploadUnusedFiles`（UI 里同一个开关），
若用真机验证需一并确认。

**以后新增 tabBar 图标 / 任何只被 app.json 引用的静态资源，先确认这个开关。**

### 纠正：必须改用 detrended_ir（i6 不能用）

- **口径**：`detrended_ir = raw_ir - dc_estimate_`（固件 EMA 去直流）；
  `filtered_ir` = detrended 之后再平滑，是 beat 检测链输入。见
  `captures/max30102_finger/20260623_153735/README.md` 第 6、7 列说明。
- **BLE 字段映射**：`i6` = `filtered_ir`，`i7` = `beat_marker`。
  `detrended_ir` 固件里算了（`heart_rate_estimator.h` 的私有成员 `dc_estimate_`）
  但**没有通过 BLE 上报**，`raw_ir` 也没上报。
- **实测（2026-06-23 手指 CSV，1505 点 / 60s / 25Hz，过服务端完整预处理后对比）**：
  - `filtered_ir`(i6) vs `detrended_ir`：相关度 **0.68**，平均相对偏差 **76%** → 不能互换
  - `raw_ir` vs `detrended_ir`：相关度 **0.987**
  - `raw_ir - avg_ir` vs `detrended_ir`：相关度 **0.9857**
  - 本地 EMA 去直流(tau=1s) vs `detrended_ir`：相关度 **0.9982**（最优回退）
- **实现**：`ppg-predict.js` 新增 `resolveSignalSource` / `detrendSignal`，
  优先级 `fullPpgDetrendedIr` > `raw-avg` > `raw 本地去直流`；
  `ALLOW_FILTERED_FALLBACK` 默认 **false**，缺字段直接报错而不是静默用 i6。
- 运行时新增 `detrendedPoints` / `rawIrPoints` / `avgIrPoints` 三路与波形对齐采集，
  落记录为 `fullPpgDetrendedIr` / `fullPpgRawIr` / `fullPpgAvgIr`（并入 wave 分离存储）。
  时间戳仍复用 `tsPoints`（同一采样网格）。
- **固件待补**：`active_realtime_batch` 加 `i5`(detrended_ir) 或 `raw_ir`(±`avg_ir`)，
  长度与 `i6` 一致。已写进 `docs/ble-interface.md` 4.5.1 与「待确认事项」。
  未补之前首页「状态识别」会明确提示缺字段。
- 验证：node 桩 wx 跑通 5 个用例（60s 带时间戳 / 无时间戳回退 / 20s 报错 /
  空波形报错 / 无时间轴报错），三文件 `node --check` 全过。
